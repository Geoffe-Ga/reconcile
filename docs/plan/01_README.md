# Reconcile: Project Refresher Pack

This zipped directory contains a set of Markdown documents that summarize (and expand on) what has been defined about **Reconcile** so far in this project, organized into topical modules.

It is written for a reader who is:
- tech savvy,
- politically curious and socially engaged,
- spiritually mystical (in the “meaning matters, but evidence matters too” sense),
- an embodied householder (busy, relational, real-world constraints),
- and on the fence about building this project, needing a total refresher.

## How to use this pack

A good reading order:
1. **02_What_Is_Reconcile.md** (the big picture)
2. **03_Core_Entities.md** (the nouns)
3. **04_Workflows_Document_Editing.md** + **07_Voting_and_Governance.md** (the verbs)
4. **05_Workflows_Reconciling_Groups.md** (coalitions and “strange bedfellows”)
5. **12_Security_Privacy_Threat_Model.md** (the “Nazis / database” concern)
6. The remaining modules, as needed, for UX, business, roadmap, etc.

## Source material used

This pack is based on:
- The project’s working **one-pager** (quoted in places).
- A set of **visual slides / diagrams** stored in `assets/` and referenced in multiple docs.
- A key **devil’s-advocate critique** raised in the project chat (included verbatim where relevant).

## A deliberate omission

This pack **does not** lock in code-level architecture or implementation choices. Where technical choices appear, they are described at the *product intent / constraints* level (e.g., “local-first vs centralized risk”), not as stack decisions.

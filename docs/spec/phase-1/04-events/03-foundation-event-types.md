### Foundation event types

| Type | Body | Valid when | Built by |
|---|---|---|---|
| `genesis` | `{name, chat?, founder, documents, rules?}`: the group name, an optional chat link, the founder's name, its Documents in order, each `{title, atoms}` (#92), and its founding rules (§11). Create group writes `rules: DEFAULT_RULES` | it is the first valid event in the mailbox; `documents` holds at least one Document, each with a title that isn't blank and is at most 120 code points as received (`documentTitleFits`; the fold never re-normalizes, and the screens check `nfcLength`, the same for any NFC title an author signs) and at least one Atom; and `rules`, when present, is an object whose every field this engine knows equals its default (§11). A `documents` that isn't a list of `{title: string, atoms: string[]}` is a bad shape, and so is a genesis that names `title` and `atoms` and no `documents` | #63 (the rules: #94; the Documents: #92) |
| `join` | `{name, level?, token?}`: the joiner's name, their involvement level (Collaborator when missing), and the inviter's token | the author isn't a member yet and hasn't left (rejoining takes a new membership key, ADR-0009), and `level`, when present, is one of `LEVELS`. The joiner holds voting rights at once only under the bootstrap (§4, Vouches and the wait before voting) | #63 (the level: #90; the token: #73; rights: #101) |
| `level` | `{level}`: the involvement level the author moves to | the author is a member, and `level` is one of `LEVELS` other than the one they hold | #90 |
| `proposal` | `{atom, title, why, text, link?, window?, dispatch?}`: the target Atom (an add carries `target: {kind: "add", document, after}` instead, never both, #75, #92, a new Document `target: {kind: "new-document", title}`, #92, a move `target: {kind: "move", atom, after}` and no `text`, #103, and a class change `target: {kind: "class", atom, to}` and no `text`, #116), the title, the justification, the proposed text, an optional discussion link, an optional voting window in whole days (#106), and an optional Dispatch `{title, text}` it sends if it passes (#112, §4 Dispatches). A priority vote is `{target: {kind: "priority"}, title, why, options, link?, window?, dispatch?}`, with no Atom or text (#107) | the author holds `propose`; an edit's Atom is in the Document the Proposal finds and has no open Proposal (#72); an add's `document` is one of the group's Documents the Proposal finds, its anchor is in that Document or null, and its text isn't `""` (#75, #92); a new Document's title fits as a genesis Document's does and its text splits into at least one section (`documentSections`, #92); a move's Atom is in a Document the Proposal finds and has no open Proposal, and its `after` is null or another Atom of that same Document, never the Atom itself (#103); a class change's Atom is in a Document the Proposal finds and has no open Proposal, and `classChangeIsValid(its class, to)` holds: ordinary to entrenched or eternal, or entrenched to eternal or back to ordinary, so never to the class it has and never from eternal (#116); an edit's, a removal's or a move's Atom isn't eternal, though an eternal Atom may anchor an add or a move (#116); the title is 1–120 code points, the justification is at most 2,000, any `window` passes `validWindow` for the Proposal's class: `Number.isInteger(window)` and `windows[class].min ≤ window ≤ windows[class].max`, and any `dispatch` fits a Dispatch's limits. A `window` that isn't a number, or a `dispatch` that isn't an object of two strings, is a bad shape. A priority vote instead needs 2–7 options, each 1–120 code points and not blank, no two the same, and no other priority vote open | #63, #75, #106, #112 (priority: #107) |
| `version` | `{proposal, text}`: the Proposal it joins, and its text, normalized as Atom text before signing | the author holds `propose`, the Proposal is open (received before its deadline and before any early close) with fewer than 3 versions, the text isn't `""` when the Proposal is an add (#75), and it splits into at least one section when the Proposal is a new Document (#92). A priority vote takes none (#107), and neither does a move (#103) or a class change (#116) | #72 |
| `vote` | `{proposal, scores, note?, salt?}`: a score from 0 to 4 for each version it names (at least one), one note, and `salt`, 16 random bytes in base64url (#111). A ballot from before #111 has no salt and still counts | the author is eligible and holds `vote`, every score names a version already on the Proposal, the note is at most 280 code points and isn't blank when any score is 0, the relay received the ballot before the deadline and before any early close, and the device hasn't cleared the Proposal's ballots | #63 (the salt: #111) |
| `result` | `{proposal, closedAt, closedSeq?, eligible, versions: [{id, counts: [n0, n1, n2, n3, n4]}], outcome, commit}`: when the Proposal closed (its early close's minute, or its deadline), for an early close the relay seq of the ballot that closed it (#289), the size of its eligible set, each version's counts in ballot order, the outcome (`{kind: "pass", version}`, `{kind: "fail"}` or `{kind: "lapse"}`) and the ballot commitment | see **Results** below | #111, #289 |
| `leave` | `{}`: the author leaves; any other field is dropped | the author is a member. They move from `members` to `former` | #77 |

The founder becomes a member at genesis, as a Co-Creator. Genesis founds its Documents in order (#92): the first keeps the genesis id and its Atoms are `${genesisId}.${i}`, and Document `k` ≥ 1 is `${genesisId}:${k}`, its Atoms `${genesisId}:${k}.${i}`. Every Atom keeps its Document's id as `documentId` (ADR-0073's seam), and its `class`, `ordinary`, `entrenched` or `eternal` (#116; ADR-0015 §2–3): every Atom starts ordinary, whether genesis founded it, an add put it in or a new Document created it, and only a class change's pass changes it. `state.documents` lists them, then each new Document whose pass is final, and `state.atoms` holds every Document's Atoms, Document by Document, each in its order. A Document whose sections were all removed keeps its place, empty. `client/src/engine/documents.ts` holds `documentTitleFits`, `documentSections`, `atomsOf` and `documentOf(state, proposal)`, the Document a Proposal changes or creates: its Atom's for an edit or a removal (found from the Atom's id once a removal has taken it out), the one an add names, or a new Document's own id. Golden vectors: `vectors/documents-*.json`.

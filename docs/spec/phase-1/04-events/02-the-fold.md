### The fold

`fold(records, relayNow, outside, cleared)` turns a mailbox's records, in relay order, into one `GroupState`, where `outside` holds the coalition motions the group's seats decide (#100, §4 Coalitions) and `cleared` lists the Proposals whose ballots the device has deleted (#111), both empty unless given: the group id (`group`, its genesis id, or null before one), the founding rules (`rules`, §11), the opt-ins in effect (`optIns`, #117), the group's name and chat link, its Documents (`documents`, each `{id, title}`, in order, #92), members (each with `invitedBy`, the key a verified invite token names, #73, and `received` and `rightsAt`, when the relay received their join and the relay minute their voting rights arrive, #101), former members (`former`: those who left, in the order they left, whose names still show on what they made, #77), Atoms, Proposals with their versions and ballots, outcomes, `at`, the steward seats (`stewards`) and suspensions (`suspensions`, #102), the steward narrowings (`narrowings`, #117), the valid vouches (`vouches`, #101), the chat bot's winning claims (`chatPosts`, #119), each Proposal's Discord thread (`chatThreads`, #123), the Dispatches (`dispatches`, #112), the key's `epoch`, its canonical key changes (`rotations`) and whether one is due (`rotationDue`, #98), the epoch the next must name (`nextEpoch`) and the key changes refused (`refused`, #224), each key change with the `kx` the group held for each recipient (`keys`), the leaves and removes this device read stranded in an old epoch's mailbox (`stranded`, #225, #376), `dissolved` (`{received, wipe}` once the group has dissolved, else null, #108), `recoveryShares` (every `recovery-share` a current member sent, in relay order, its box unopened, #109), `recoveryAlerts` and `recoveryCancels` (every `recovery-alert` and `recovery-cancel`, #118), and `ignored` (#63, #69). A member also carries `kx`, their encryption key, or null (#98). Each Proposal carries `number`, its 1-based place among the group's Proposals in relay order, counting only the ones the fold kept (#123; `vectors/proposal-number.json`). A coalition motion opened from `outside` (#100, §4 Coalitions) is 0 and isn't counted, so a group's own numbers don't depend on whether a device has the coalition's log yet (`vectors/coalition-group.json`). `at` is the relay minute the state stands at: the fold sets it to each record's `received` before checking it (it never moves back), and to `relayNow` at the end, or to the latest `received` when that's null, so `can()` reads relay time with its three arguments. Once the group has dissolved, `at` stays at the dissolve's `received` (Dissolution, below). Before each record, and once more at the end, the fold brings the steward seats, the standing opt-ins and the Dispatches passed Proposals carry up to `at` (§4, Stewards and suspensions; Opt-ins; Dispatches). For each record, the fold first checks the epoch of the mailbox it was read from (`LogRecord.epoch`, absent for 0, #98): a record of any other epoch than the group's current one changes nothing, not even `at`, and claims no event id, so the copy its author posts again to the new mailbox folds once. Then it:

1. verifies the signature before it parses the event, and requires `author` to equal the record's key. A record that fails lands in `ignored` with `id: null` and claims no event id, so a forged copy of a real event never shadows it;
2. drops a repeated event id, so the first copy keeps its seq and receipt time;
3. ignores an event whose `v` isn't 1 or whose `group` isn't the genesis id (unknown versions are ignored, ADR-0073), and every event after a `dissolve` (#108). `admits` in `client/src/engine/fold.ts` is this one guard;
4. ignores an event from a non-member, except that person's own `join`: `can()` is false for anyone who isn't a member. It also ignores every event from a member whose suspension is running, except their `leave` (#102, #77) and their `recovery-share`, `recovery-alert` and `recovery-cancel`, which govern nothing (#109, #118);
5. checks the event's rules against the state before it. An event that breaks a rule lands in `ignored` and changes nothing.

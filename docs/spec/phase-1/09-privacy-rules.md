## 9. Privacy rules

Every issue, foundation or restored, keeps these. The threat model is [`12_Security_Privacy_Threat_Model.md`](../../plan/12_Security_Privacy_Threat_Model.md).

- **No accounts and no IP logs.** The relay drops client addresses and forwarding headers before any route runs. Caddy discards its logs, and the VM keeps its journal in memory only (#62, #68). Whoever runs the relay can still see connecting IP addresses and timing live, and the pilot notice says so.
- **Padded, sealed blobs.** Everything a device sends the relay, but for public shelf records (below), is a sealed blob of one of the four sizes, under a mailbox id derived from a secret only members hold. The author and the signature sit inside the seal (ADR-0019). A relay backup (#97) is one sealed blob of one of five sizes under an id derived from a key only the person's devices, backup file and, after #109, chosen contacts hold, linked to no mailbox, written at most once a relay day by each device that keeps the key, and read once before each write (#247). Uploads come from the same IP address as the device's group syncs, so whoever watches the relay live can tie the backup to those groups (ADR-0075 §2). A choice of recovery contacts overwrites the replaced key's id with random bytes, which the relay can tell from a backup, and the device that chose reads that id once a relay day and writes random bytes again when needed (#272): from the same IP address, under an id the relay already saw it write, naming no other id, device or contact. The split id that travels with the key never reaches the relay.
- **The one readable exception: the public shelf** (#484, [ADR-0081](../../adr/0081-listed-doors-and-exception-moderation.md), [`listed-doors.md`](../listed-doors.md) §7). Shelf records are the only bytes a device sends that the relay can read, and the only ones the relay keeps readable. They are signed, unsealed and unpadded: a listed door's name, its covenant hash and the Dispatches its group voted to publish, each an id, a title and a text. A record names no person: no member's name, key or id, no author, count or ballot. It is signed with the door's own key, never a member's, so it ties to no membership. The routes are off until the relay holds the steward's key, so nothing is readable on a relay without it. Every device reads the whole shelf, so a read says nothing about its reader, and reads it at most once an hour. A live observer can still tie a listed group's name to the IP addresses of the members' devices that post its records, and so to the sealed mailboxes those devices sync from the same addresses: each member's device posts the listing after its group syncs (#486). The pilot notice says so ("if your group lists its front door on the public shelf, that your device is in that group, since your device posts the listing"), and so does the listing's covenant ("Members' devices post the listing, so whoever runs the relay can tell which devices are in your group."). Accepted for the pilot; it goes to the outside review (ADR-0058; [`listed-doors.md`](../listed-doors.md) §7 and §9).
- **The relay is trusted only for order and time** (ADR-0073). It can't read, forge or link anything it stores, but for the public shelf, whose records it can read but still can't forge, since every device verifies each one.
- **A front door shows no one** (#121, ADR-0038). Its page carries the group's name, an excerpt and, only if chosen, a count, never a member's name, key or id. Its secrets live only in the sealed log; applications are sealed to its key and replies to a key only the applicant's device holds, and an applicant gives no contact details. Whoever leaves or is removed keeps the secrets they could read, so the door closes when a membership ends and opens again only with new ones (#288). Doors aren't listed anywhere (ADR-0038's index stays deferred). An application may carry a copy of personal Documents the applicant checks, none to start (#425, ADR-0077 §3): only their titles and text, sealed and padded inside the one application, never a share link, an id, a time or a key, so nothing reusable ties one application to another (ADR-0009). The same words sent to two groups can still be compared by them, and the form says so. The applicant's device keeps no copy; each member's device keeps it beside the name and message, never in a backup, and deletes it when the application is dismissed there or once an invite to it folds. A door also takes reconcile cards (#426, ADR-0077 §5): only a card's seed goes into the inbox, sealed to the door's key and padded, so a card tells one group that one other group exists, its name and that someone there wants to reconcile, naming no person but the name the sender chose for the coalition. The relay sees one more padded blob in the inbox, posted beside the card's own envelope from the same address. A member's device keeps the seed only until the card is closed or surely gone, and `door-card-closed` names only the card's blob by its SHA-256. A door's inbox can be filled with cards as with applications; nothing caps them yet.
- **Secrets stay after `#`.** Invite seeds, group secrets and share seeds travel only in the URL fragment, and the app removes invite seeds and group secrets from the address bar once read (#65, #73, #76). A share link's seed stays there, so a reload reads it again: it opens one personal Document, read-only, and nothing of anyone's groups (#105). A linking code (#96) never enters a URL at all: it's shown, scanned or pasted, and held in memory while its screen is open. Beside Copy invite link: "Anyone who opens this link in the next 2 days can read everything this group has written and voted on, and what comes next. Send it directly to the people you're inviting."
- **Open ballots, inside the group only** ([ADR-0010](../../adr/0010-open-ballots-with-exit.md)). Everyone in the group sees each other's names and ballots, and nobody outside it sees either. Every level can read ballots and vouches until the hidden roster returns (ADR-0075 §5).
- **Shares carry no content.** Tell your group sends a fixed message, a deadline and the vote's link (#472, [ADR-0079](../../adr/0079-vote-links.md)). The Proposal's title goes in only when the person ticks Include the title for that one share, and never for a steward Proposal. A share never carries Document text, a group name, a member's name, a link fragment or a secret, and Web Share gets no `title` field (#77, #113). The exceptions are links whose fragment is the point. Share link (#105) hands on a share link beside fixed words, never the Document's title or text. A recovering device's code (#118) goes beside fixed words and the app's address. Share beside a reconcile card's link or a follow link (#424; ADR-0077 §6) hands the share sheet that link alone, with no words, and copies it where there's no sheet; the line by the button says that whoever runs a chat app it goes through can read the link too, for the 2 days it works. A vote link (#472, ADR-0079), `#vote/{token}`, is one of these links: Tell your group's share and the Discord bot's notices (ADR-0039) end with it, and Copy link to this vote copies it. Its token is the first 16 bytes of HKDF-SHA-256 of the group's secret under `reconcile/v1/vote-link` ‖ 0x00 ‖ the Proposal's id, in unpadded base64url, so it names no group and no Proposal, one coalition motion's links in two groups have nothing in common, and to whoever runs the chat it says only that a vote exists. A device computes a token when it shares or opens a link: no token is stored, backed up or sent to the relay, and a key change retires older links.
- **Nothing third-party.** There are no analytics, telemetry, third-party scripts or third-party fonts. The app calls only the relay, plus the browser's push service once a person turns push on (#99), and a Discord webhook for a group that turned its bot on by Proposal (#119).
- **Script defense.** The CSP `default-src 'self'; script-src 'self'; style-src-elem 'self' 'sha256-…'; connect-src 'self' https://discord.com/api/webhooks/; object-src 'none'; base-uri 'none'; frame-ancestors 'none'` (#68) and `<AtomText>` (#70, §8.6) are the main defense against injected script stealing keys. Its one hash, in full in `deploy/Caddyfile`, allows React Aria's iOS scroll-lock `<style>` and nothing else (#153, [deploy/README.md](../../../deploy/README.md#the-csp)); it never allows `'unsafe-inline'`. Atom text never becomes HTML, links are limited to `http:`, `https:` and `mailto:`, and the renderer loads nothing: images are off, so no Atom can make a device fetch. The linking code (#96) needs no change to it: the QR code is an inline SVG, never a `data:` image, and the decoder runs on the main thread, with no `blob:` worker or WebAssembly. No `Permissions-Policy` header is sent, so the camera is the browser's default, the app's own origin, and the page asks for it only after a tap.
- **Local data.** Leave deletes every record of the group from the device once the relay has the leave (#77), and every coalition only that group held there, as a removal or a dissolve does (#278), but for the push `DELETE`s the device still owes when push was on: the endpoint and each mailbox id, kept until each is sent, within the day (#356, §7 Push). The relay backup's record (#97) never holds a group's id, only a tag keyed by the backup key, and drops even that once a read finds the relay copy without the group (§3, #327). A dissolve sends nothing more and ends all traffic for the group; with wipe, each device deletes every record of it a week later, and without, each clears the copy's ballots, notes and vouches 30 days later (#222). The composer says no app can stop someone who already kept a copy, a screenshot or a backup file (#108). Erase deletes all of Reconcile's data on the device and makes no network call (#78): `eraseDevice` halts the sync loop, so no request starts after it and the chat bot (#119) claims and posts nothing, and closes the store, since an open connection blocks `deleteDatabase` (another tab's store closes itself when asked). It then deletes every database, the store's and any that `indexedDB.databases()` lists, empties Cache Storage, `localStorage` and `sessionStorage`, unregisters every service worker, and only when all of that succeeded calls `location.replace('/')`, which opens on first run with no groups. The passkey vault goes with the database (#95); the passkey itself stays in the person's password manager, named "Reconcile key", until they delete it there. Erase sends no push `DELETE` (#99): one would tell the relay this phone had just erased. Unregistering the worker ends the push subscription, so the push service refuses the relay's next push to it with 404 or 410, and the relay forgets that endpoint under every mailbox (#89); the relay drops any registration after 30 days in any case. The backup file is sealed, never uploaded, and holds no readable name, text, key or secret. A link's bundle (#96) reaches the relay only sealed under a key the relay never sees, in a mailbox it can't tie to the group, and each device zeroes the link's secrets once it's done. Private drafts live inside the group's record, so both remove them, and nothing ever sends one (#70). Personal Documents live in the same database, so Erase deletes them too, and Leave never touches them (#93). A dissolve's wipe and its clearing leave them alone too (#108).
- **ADR-0074's restored protections:** a new group key whenever someone leaves or is removed, with per-member encryption keys (#98, #115); mailboxes that rotate weekly (#110); and ballots and notes that expire 30 days after a decision, a coalition's motion's included (#278), leaving a signed result (#111, §4 and §7: after the window no ballot score or note stays anywhere on the device, and the Service Worker never caches `/v1`, so Cache Storage holds none either). A new secret leaves a device only inside per-member boxes, so the relay sees one more padded blob and a new mailbox id. Until the rest merge, the foundation runs with ADR-0073's other accepted risk: there are no recovery contacts.
- **Accepted pilot risks,** which the outside review covers ([ADR-0058](../../adr/0058-security-review-on-demand.md), #132):
  - the relay is trusted for order and time (ADR-0073);
  - coalition keys don't rotate, and push shows the relay some metadata (ADR-0074);
  - anyone holding a coalition seat secret can block a motion or act in the coalition, push and polling show the relay which groups share a phone, and colluding recovery contacts can skip the wait (ADR-0075).

# Reconcile Client (TypeScript PWA)

This is the member-device app: UI, group engine, keyring, and encrypted local store. **Read the root [`CLAUDE.md`](../CLAUDE.md) first.** Its domain vocabulary, the "Defend Against Weaponization" constraint, and the ADRs all apply here unchanged.

- **What to build:** [`docs/spec/phase-1-spec.md`](../docs/spec/phase-1-spec.md): its Identity and keys, Events, Tally, Relay API, Sync, Screens and Privacy rules sections describe the foundation, and Restored features names the issue that builds each later feature
- **Why:** ADR-0073 and ADR-0074 (MVP scope: what to build now, and how deep), ADR-0075 (its safeguards), ADR-0005 (PWA), 0006 (signed log), 0008 (keys and recovery), 0009 (per-group identities), 0017 (visibility), 0018 (device protection), 0022 (React + Vite + React Aria), and 0023 (Markdown Atoms) in [`docs/adr/`](../docs/adr/README.md)
- **Look and voice:** [`DESIGN.md`](../DESIGN.md). `src/styles/tokens.css` mirrors it: change DESIGN.md first.
- **Contract:** governance logic must pass the golden JSON vectors in `src/engine/vectors/` and the fast-check properties beside them. The TypeScript engine is the only implementation ([ADR-0073](../docs/adr/0073-mvp-scope.md))

## Commands

Run from `client/`, or run `./scripts/check-all.sh` from the repo root, which runs this gate when `client/` changed.

```bash
npm ci
./scripts/check-all.sh   # lint, format, typecheck, tests + coverage, architecture, npm audit, tracked sources
./scripts/e2e.sh         # the end-to-end loop in Chromium and WebKit, through the real relay
./scripts/mutation.sh    # Stryker (Vitest runner), ≥80%; recommended before a release, not a merge gate
npm run dev              # local dev server
npm run build            # production build
```

### End-to-end loop

`e2e/loop.spec.ts` is the tracer loop: three browser profiles create a group, join it from the invite link, propose, vote (one of them offline) and see the Update. axe runs on every screen they visit, and any CSP violation fails the run. `e2e/versions.spec.ts` runs competing versions on a phone and a desktop, `e2e/leave.spec.ts` Tell your group and Leave (#77), and `e2e/dissolve.spec.ts` a group that votes to dissolve, whose devices then keep a read-only copy and never name its mailbox again (#108). `e2e/relay-learns-nothing.spec.ts` (#71) runs a loop with a canary in every field, stops the relay, and scans the raw bytes of its database, WAL, shared memory and log for any canary, key or the testers' IP address, in every encoding (`e2e/support/scan.ts`). Its control blob must turn up, so the scan can't pass by reading nothing. `e2e/invite-history.spec.ts` (#73) passes a Proposal, deletes the group's oldest relay rows, genesis included, from the relay's SQLite file with `node:sqlite`, and checks that a newcomer joining from a fresh link sees the same Document and people. It also captures every request and fails on any group secret, invite seed or invite key in a path, query or body. `e2e/vouch.spec.ts` (#101) covers a fourth joiner’s wait for a vote and a vouch for them. `e2e/backup.spec.ts` (#78) saves a backup through the download path, scans the file for canaries and keys in every encoding, restores it on two fresh profiles that then vote as one person, `e2e/relay-backup.spec.ts` (#97) restores a backup file that carries a relay backup key on a fresh phone, checks that its first complete sync pass uploads one padded blob that opens under the key and that Settings says so, then stops the relay and scans its database, WAL, shared memory and log for canaries and keys in every encoding, with the blob and its id as controls, and `e2e/erase.spec.ts` erases a seeded profile, capturing every request, and checks the reloaded app shows first run with no records. `e2e/personal.spec.ts` (#93) writes a canary mission statement in Personal, previews, reloads, deletes, and proposes in a group meanwhile, capturing every request, then checks that no request, no group record and nothing the stopped relay kept carries it. `e2e/leave-rotates.spec.ts` (#98) reads a member's group secret from IndexedDB, has them leave, waits for the others to take up the new key, and opens every blob the relay holds with keys derived from the old secret: none holds the next Proposal's canary title, while the new secret's keys open it. The leaver's earlier invite link then shows the no-wrap line, and the stopped relay's files hold neither secret nor any device's encryption key. `e2e/removal.spec.ts` (#115) has Ana and Ben vote Cal out: Cal posts his one response, the removal closes early, his profile shows the removed line and names the group's mailboxes no more, and every blob sealed after the key change, which no key of his opens, keeps the next Proposal's canary from him. `e2e/dispatch.spec.ts` (#112) has a Co-Creator send a canary Dispatch and a Proposal carry one, and a Member who follows read both, capturing every request: the Dispatch's PUT asks for `wake=1`, and no request or file the stopped relay kept carries its words. `e2e/weekly-mailboxes.spec.ts` (#110) checks that everything the app writes goes to this week's mailbox, as Node's own HKDF derives it, then plays a device whose GET still said last week: it posts a Proposal to last week's mailbox, which the others fold and vote on from this week's, and a newcomer then holds the whole history. The stopped relay holds the group under exactly those two ids, each blob sealed to its own, and neither the retired single id nor the secret. The real relay's clock can't be moved, so the spec skips itself within 15 minutes of Thursday 00:00 UTC, and the unit tests (`src/store/sync.test.ts`, with the fake relay's clock) cover weeks turning under real devices. `e2e/passkey.spec.ts` (#95, Chromium only: WebKit has no virtual authenticator) locks keys with a passkey on a CDP virtual authenticator at `localhost`, since a passkey's relying party can't be an IP address, scans IndexedDB for any key outside the vault, the relay backup key (#97), a shared Document's seed and keys (#255) and a sent application's reply keys (#265) included, each found by the same scan before the lock as a control, checks that a locked page sends the relay nothing, and unlocks after a reload; without PRF, the keys stay plain. `e2e/share.spec.ts` (#105) shares that statement by link: a second profile that never opened Reconcile reads it with no pilot notice and keeps no database, storage, cache or worker, sees Ana's edit after a reload and the not-shared line once she stops, every request from either browser is free of the share's seed and keys and of any group id or secret, and the stopped relay keeps no canary but does keep the share's mailbox id. `e2e/recovery.spec.ts` (#109) has Ana pick three of four others as recovery contacts at 2 of 3, checks who sees which line, opens each contact's box outside the app with their own key and rebuilds her backup key from any two, chooses again without one and checks the old backup id holds 64 KiB that open under no key, then fails on any request or stopped-relay byte carrying a key, share, split, contact's name or contact's key, with a backup and its id as controls. `e2e/front-door.spec.ts` (#121) opens a group's front door by an entrenched vote that closes early; a fresh profile accepts the notice, reads the page with no member's name, asks to join, is invited from Applications and joins as a newcomer, while every request from all four browsers is free of the group secret, members' names and keys, the door's secrets, the reply seed and key and the applicant's words, with the inbox and reply mailbox as controls, and the stopped relay keeps no canary but does keep the inbox's id. These specs share `e2e/support/`, and take its steps rather than copying them: `steps.ts` (first run, found, join, open a vote and score it), `coalition.ts` (make and bring a card, and the coalition's keys for a scan), and `fixtures.ts`: its `relay` fixture runs the real relay for each test, its `openProfile` fixture fails the test on any CSP violation in any profile and answers every request a profile sends to Discord itself, as a forum channel's webhook would, keeping each in `openProfile.discord` and failing the test on any it didn't answer, so no test posts to Discord (#119, #123), and `expectAccessible` runs axe with contrast on. WebKit never lets `context.route` see a request from a page under the app's service worker, and it reloads a page sent to its own URL, which puts the page under the worker, so specs move a page with `visit`, which never reloads it; `e2e/fixtures.spec.ts` checks `visit` and the unanswered-request check in both browsers (#123). `e2e/reconcile.spec.ts` (#114) has two profiles found a group each; one makes a reconcile card, the other brings it to their group, each group passes its reconcile Proposal, and both group homes list the coalition as formed; then it stops the relay and scans its files for the coalition's name, statement and every coalition name, both group names, and the coalition's secret, seal key and keys and the card's seed and key, in every encoding, with a control blob, the coalition's weekly mailbox ids and the card's mailbox id as controls. `e2e/follow.spec.ts` (#124) forms that coalition, has a participant share a follow link from its home, and has a third profile in neither group open it, accept the notice, read the preview as plain text, follow and read the coalition as a follower, then unfollow; every request that profile sends is free of the coalition's secret and seal key, each group's `inner` and seat secret, and the link's seed and key, with the follow mailbox's id as a control, its IndexedDB keeps the coalition's secret but no `inner` or seat secret, and nothing of the coalition once it unfollows, and the stopped relay keeps no canary, with a control blob, the coalition's weekly mailbox ids and the follow mailbox's id as controls. `e2e/coalition.spec.ts` (#127) runs a coalition through four profiles: Ana founds A and Ben founds B, Dee joins A as a Collaborator, and Cy joins A as a Collaborator and B as a Co-Creator. Cy brings Ana's card to B, both groups pass, and every profile sees the coalition formed, Cy's device holding it once. One coalition change passes group by group, with A's profiles waiting for 1 more group first, and a second fails when B scores it 0. Dee and Ana, in A alone, never see B's reasons on any screen (`e2e/support/watch.ts`) nor B's totals. Then every profile reads the relay's clock a week past the pass's deadline, and each coalition home shows the first change and not the second. The stopped relay keeps no group, coalition, motion or reason canary and no secret or key, with a control blob and every mailbox id as controls. `e2e/room.spec.ts` (#125) has two groups reconcile and both people open the coalition's room from its home: one writes, the other answers with a script in the text, and both list the same messages in the same order, the script as text; then it stops the relay and scans its files for both messages, both coalition names, the room's `inner`, seal key and entry id and each coalition key, in every encoding, with a control blob and the room's weekly mailbox ids, from `inner` by Node's own crypto, as controls. `e2e/discord-threads.spec.ts` (#123) turns the bot on, checks that a Proposal's first notice opens its thread, 'Proposal 2 in Reconcile', that Join discussion then opens that thread, and that its result goes into it as the concluded line. `e2e/double-tap.spec.ts` (#193, Chromium only) double-taps Send your vote and Propose this change while it holds the app's group store in a transaction of its own, so the second tap lands on the disabled button, and counts one submit event each; the Proposal fails to save because the test opens the database at a newer version, as a newer tab would. `e2e/ios-scroll-lock.spec.ts` builds `e2e/ios-modal/`, a test-only page with one React Aria Modal, into a temp directory and serves it with `vite preview` and the app's config, until a screen of the app opens a modal (#153).

- **Run it** with `./scripts/e2e.sh`, never bare `npx playwright test`. The script picks two free loopback ports (`E2E_WEB_PORT`, `RECONCILE_RELAY_PORT`) and puts the relay's database (`RECONCILE_RELAY_DB`) and its stdout and stderr (`E2E_RELAY_LOG`) in a temp directory it deletes afterwards. It builds the app, then runs Playwright, whose config starts `vite preview` (which sends the deploy CSP). Each test starts `../scripts/relay.sh` itself and stops it when it ends (`e2e/support/fixtures.ts`), because Playwright can't stop a `webServer` mid-run and the scan needs a stopped relay.
- **Browsers:** install them once with `npx playwright install chromium webkit` (on Linux, add `--with-deps`). On a machine where WebKit won't install, `E2E_PROJECTS=chromium ./scripts/e2e.sh` runs Chromium alone and says so. CI always runs both.
- **Arguments** go to `playwright test`: `./scripts/e2e.sh --project=chromium --headed`, or `--trace on` to debug. A run that matches no test fails.
- **Gate:** the repo root's `./scripts/check-all.sh` runs it whenever `client/`, `reconcile/`, `requirements.txt` or `scripts/relay.sh` changed, and CI's `e2e` job runs `./scripts/check-all.sh --e2e`. It stays out of this directory's `check-all.sh`, so the client gate needs no browser.
- **Rules:** keep `bypassCSP` off, and don't add a test-only relay mode or route, or time travel (`page.clock`): the relay runs exactly as `relay.sh` starts it. The one clock a spec may move is the `now` a profile reads from the relay's mailbox GETs, with `readRelayLater` (`e2e/support/relayNow.ts`, #127), which rewrites that one field in Playwright and nothing the relay keeps. Move every profile at once, and only once nothing more has to cross between them: a moved device writes to a later week's mailbox (#110).
- **Beside the loop** (#76): `offline.spec.ts` (Chromium only) reloads offline under the service worker, `ios-gate.spec.ts` opens iPhone profiles at the install gate, and `csp.spec.ts` brings the worker up under the deploy CSP and checks that the page connects only to its own origin and Discord's webhook path (#119), from `e2e/support/connect.ts`, the one file outside `src/net/` that may call `fetch`. `push.spec.ts` (#99) runs in Chromium itself rather than its headless shell, which has no notifications: it checks Settings › Notifications under the deploy CSP, then delivers pushes straight to the service worker over the DevTools protocol, with no push service, and, once DevTools logs that the worker has finished each one, reads in the worker that it shows only "Something new in Reconcile". A read while the worker shows a notification would race it (Chromium drops its record of one not yet on display). Every new profile accepts the pilot notice first (`acceptNotice` in `e2e/support/fixtures.ts`), which also answers the passkey offer Not now wherever it follows (#95), except a share link's reader in `share.spec.ts`, which meets the notice only once it leaves the link, since the shared page sits outside first run (#105).

## Client rules

- **No hand-rolled cryptography.** Use audited `@noble/*` libraries (spec, Identity and keys), plus `shamir-secret-sharing`, pinned exactly and imported only by `src/crypto/shares.ts`, tests included (dependency-cruiser holds it; [ADR-0075](../docs/adr/0075-safeguards-for-the-revised-mvp.md) §4).
- **Recovery contacts stay on the device** (#109). The contact list is one record in the store's `device` object store that no snapshot carries; only sealed `recovery-share` boxes leave, each naming no one.
- **QR codes** (#96) come from `qr`, a dependency-free encoder and decoder that does no cryptography, imported only by `src/app/qr.ts` (dependency-cruiser holds it).
- **Nothing readable leaves the device.** Anything sent to the relay is a sealed, padded, encrypted blob (ADR-0019).
- **No analytics, telemetry, or third-party scripts.** The app's only network calls go to the relay and, once a group has turned its bot on by Proposal, that group's Discord webhook (#119). Only `src/net/relay.ts`, `src/net/push.ts` (the relay's push routes, #99) and `src/net/discord.ts` call `fetch`, and the deploy CSP's `connect-src` allows nothing but the app's own origin and `https://discord.com/api/webhooks/`. Push (#99) needs no CSP change: the browser talks to its own push service, and the page only calls `pushManager` through `src/platform/pushPort.ts`.
- **Push carries nothing** (#99, ADR-0012). Every notification is exactly "Something new in Reconcile" with the tag `reconcile` and no other option (`src/sw/notify.ts`), push request bodies hold only `endpoint` or `not_before`, and registrations and nudges take their mailbox only from `mailboxAt` (`src/store/mailbox.ts`), which follows the group's current key (#98) and the relay's week (#110). A read-only archive (#108) sends no push request at all. Tests use `src/test/fakePush.ts`, never a real push service.
- **Quiet safety:** protective features live in Settings and aren't promoted (ADR-0018).
- **First run gates keys.** Nothing makes keys behind the iOS install gate or before the pilot notice (`src/app/FirstRunGate.tsx`, spec §8.1). A device whose keys are locked with a passkey syncs, sweeps archives and signs nothing until the unlock screen opens them (#95). Every write of key material, the relay backup key (#97), a shared personal Document's seed and keys (#255) and a sent application's reply keys (#265) included, goes through the store's one write path, `keepKeys`, which seals it into the vault when there is one and refuses while it's locked, and anything that hands keys on (Save a backup, Link a new device, #96) calls `Store.requireUnlocked()` first. A record that keeps secrets beside what it says splits through `src/store/sealing.ts`, one mechanism for every such store: its secrets go into the vault by store and id, and the record keeps the rest, so a new kind (#303's recovery request) adds a sealing, not a vault format. Only `src/platform/webauthn.ts` reaches `navigator.credentials` (ESLint enforces it). The service worker is `src/net/serviceWorker.ts`, built to `/sw.js` by `plugins/serviceWorker.ts`; it never caches `/v1`, and its push and notification-click handlers come from `src/sw/notify.ts` (#99).
- **A busy control holds presses** (#193). React Aria's usePress starts a press on a disabled control and clicks it itself 80 ms later, which re-sends a submit button's form or flips a checkbox, radio or switch once it's enabled again. So a control disabled while its action runs takes `holdPresses` (`src/app/holdPresses.ts`) as `onPointerDownCapture` on it or its row. ESLint holds every disabled submit `Button` to this; check toggles by hand. A plain `onPress` button needs nothing, since no `onPress` runs for a press that started while disabled.
- **Keep the CSP clean.** The deploy CSP (spec §9) blocks inline `<style>` elements, `style` attributes in markup and `data:` URLs. React's `style` prop is fine: it sets styles through the CSSOM. React Aria's pressable `<style>` is claimed in `index.html`, and `src/styles/pressable.css` ships its rule instead; `src/styles/pressable.test.tsx` fails if React Aria changes it (#150). Its iOS scroll-lock `<style>` has no id, so the CSP allows that one text by its hash in `style-src-elem`; `src/styles/scrollLockStyle.test.tsx` fails if React Aria changes it, and `e2e/ios-scroll-lock.spec.ts` opens a Modal as an iPhone under the CSP (#153). Never add `'unsafe-inline'`.

## Toolchain

- **Stack:** React 19, Vite, TypeScript (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), and React Aria Components
- **Testing:** Vitest + Testing Library (globals off: import `describe`/`it`/`expect` from `vitest`), and Playwright with `@axe-core/playwright` for the end-to-end loop (`e2e/`, `tsconfig.e2e.json`)
- **Linting:** ESLint 9 flat config with `strictTypeChecked`, jsx-a11y strict, and complexity ≤ 10
  - ESLint stays on 9 until `eslint-plugin-jsx-a11y` supports 10
- **Coverage:** ≥ 90% lines, ≥ 85% branches, enforced in `vite.config.ts`
- **Architecture:** `plans/architecture/.dependency-cruiser.cjs`
  - `src/engine`, `src/crypto`, `src/store` and `src/door` (#121) may not import React or UI code
  - network libraries belong in `src/net/` only
  - only `src/crypto` imports `@noble/*`, and `src/crypto` imports no other third-party package but `shamir-secret-sharing`, which only `src/crypto/shares.ts` imports (#109)
- **Tracked sources:** `scripts/tracked.sh` fails when git ignores anything in `client/` but tool output, because CI's checkout wouldn't have it (the root's Python `build/` rule once hid `client/build/`, #76)
- **Audit:** `npm audit --audit-level=moderate`
  - `package.json` `overrides` pin `minimatch` and `qs` to patched releases. Remove an override once its upstream package ships the fix
- **Fonts:** self-hosted through `@fontsource-variable/*`, never fetched from a third party

Detailed generic guidance is in [`.claude/docs/`](.claude/docs/).

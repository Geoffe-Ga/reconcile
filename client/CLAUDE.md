# Reconcile Client (TypeScript PWA)

This is the member-device app: UI, group engine, keyring, and encrypted local store. **Read the root [`CLAUDE.md`](../CLAUDE.md) first.** Its domain vocabulary, the "Defend Against Weaponization" constraint, and the ADRs all apply here unchanged.

- **What to build:** [`docs/spec/phase-1-spec.md`](../docs/spec/phase-1-spec.md): its Identity and keys, Events, Tally, Relay API, Sync, Screens and Privacy rules sections describe the foundation, and Restored features names the issue that builds each later feature
- **Why:** ADR-0073 and ADR-0074 (MVP scope: what to build now, and how deep), ADR-0075 (its safeguards), ADR-0005 (PWA), 0006 (signed log), 0008 (keys and recovery), 0009 (per-group identities), 0017 (visibility), 0018 (device protection), 0022 (React + Vite + React Aria), and 0023 (Markdown Atoms) in [`docs/adr/`](../docs/adr/README.md)
- **Look and voice:** [`DESIGN.md`](../DESIGN.md). `src/styles/tokens.css` mirrors it: change DESIGN.md first.
- **Contract:** governance logic must pass the golden JSON vectors in `src/engine/vectors/` and the fast-check properties beside them. The TypeScript engine is the only implementation ([ADR-0073](../docs/adr/0073-mvp-scope.md))

## Commands

Run from `client/`, or run `./scripts/check-all.sh` from the repo root, which runs this gate when `client/` changed.

```bash
npm ci
./scripts/check-all.sh   # lint, format, typecheck, tests + coverage, architecture, npm audit, tracked sources
./scripts/e2e.sh         # the end-to-end loop in Chromium and WebKit, through the real relay
./scripts/mutation.sh    # Stryker (Vitest runner), ≥80%; recommended before a release, not a merge gate
npm run dev              # local dev server
npm run build            # production build
```

- **Run it** with `./scripts/e2e.sh`, never bare `npx playwright test`. Playwright runs two workers (`E2E_WORKERS`), and each has servers of its own: the script picks two free loopback ports per worker (`E2E_WEB_PORTS`, `E2E_RELAY_PORTS`) and puts each worker's relay database and its stdout and stderr (`relay-N.db`, `relay-N.log`) in a temp directory (`E2E_RELAY_DIR`) it deletes afterwards. It builds the app, then runs Playwright, whose config starts a `vite preview` (which sends the deploy CSP) for each worker, proxying `/v1` to that worker's relay port. Each test starts its worker's `../scripts/relay.sh` itself and stops it when it ends (`e2e/support/fixtures.ts`), because Playwright can't stop a `webServer` mid-run and the scan needs a stopped relay. A worker runs its tests one at a time, and no test reaches another worker's pages, relay, database or log.
- **Browsers:** install them once with `npx playwright install chromium webkit` (on Linux, add `--with-deps`). On a machine where WebKit won't install, `E2E_PROJECTS=chromium ./scripts/e2e.sh` runs Chromium alone and says so. CI always runs both.
- **Arguments** go to `playwright test`: `./scripts/e2e.sh --project=chromium --headed`, or `--trace on` to debug. A run that matches no test fails.
- **Gate:** the repo root's `./scripts/check-all.sh` runs it whenever `client/`, `reconcile/`, `requirements.txt` or `scripts/relay.sh` changed, and CI's `e2e` job runs `./scripts/check-all.sh --e2e`. It stays out of this directory's `check-all.sh`, so the client gate needs no browser.
- **Rules:** keep `bypassCSP` off, and don't add a test-only relay mode or route, or time travel (`page.clock`): the relay runs exactly as `relay.sh` starts it. The one clock a spec may move is the `now` a profile reads from the relay's mailbox GETs, with `readRelayLater` (`e2e/support/relayNow.ts`, #127), which rewrites that one field in Playwright and nothing the relay keeps. Move every profile at once, and only once nothing more has to cross between them: a moved device writes to a later week's mailbox (#110).
- **Beside the loop** (#76): `offline.spec.ts` (Chromium only) reloads offline under the service worker, `ios-gate.spec.ts` opens iPhone profiles at the install gate, plainly and with an invite link, a reconcile card's link and a vote link, which the guide holds to copy (#280, #472), and `csp.spec.ts` brings the worker up under the deploy CSP and checks that the page connects only to its own origin and Discord's webhook path (#119), from `e2e/support/connect.ts`, the one file outside `src/net/` that may call `fetch`. `push.spec.ts` (#99) runs in Chromium itself rather than its headless shell, which has no notifications: it checks Settings › Notifications under the deploy CSP, then delivers pushes straight to the service worker over the DevTools protocol, with no push service, and, once DevTools logs that the worker has finished each one, reads in the worker that it shows only "Something new in Reconcile". A read while the worker shows a notification would race it (Chromium drops its record of one not yet on display). Every new profile presses the landing page's Start a Group when it shows, then accepts the pilot notice, and `e2e/landing.spec.ts` covers the landing page itself (ADR-0078) (`acceptNotice` in `e2e/support/fixtures.ts`), which also answers the passkey offer Not now wherever it follows (#95), except a share link's reader in `share.spec.ts`, which meets the notice only once it leaves the link, since the shared page sits outside first run (#105).

## Client rules

- **No hand-rolled cryptography.** Use audited `@noble/*` libraries (spec, Identity and keys), plus `shamir-secret-sharing`, pinned exactly and imported only by `src/crypto/shares.ts`, tests included (dependency-cruiser holds it; [ADR-0075](../docs/adr/0075-safeguards-for-the-revised-mvp.md) §4).
- **Recovery contacts stay on the device** (#109). The contact list is one record in the store's `device` object store that no snapshot carries; only sealed `recovery-share` boxes leave, each naming no one. Recovering (#118, `src/recovery/`) keeps it so: a contact's holds stay on its own group record, an alert is a box to the person, a cancel names only a tag sealed in that box, and a released share goes to the request mailbox sealed twice, so no event names who helps whom.
- **Look-alike names** (#487) are compared by a UTS #39 skeleton (`src/shelf/skeleton.ts`) built from Unicode's `confusables.txt`, vendored as the generated table `src/shelf/confusables.ts`. Regenerate it only with `node scripts/confusables.mjs`, which checks the source file's SHA-256; `skeleton.test.ts` pins the table's hash.
- **QR codes** (#96) come from `qr`, a dependency-free encoder and decoder that does no cryptography, imported only by `src/app/qr.ts` (dependency-cruiser holds it).
- **Nothing readable leaves the device.** Anything sent to the relay is a sealed, padded, encrypted blob (ADR-0019).
- **No analytics, telemetry, or third-party scripts.** The app's only network calls go to the relay and, once a group has turned its bot on by Proposal, that group's Discord webhook (#119). Only `src/net/relay.ts`, `src/net/push.ts` (the relay's push routes, #99) and `src/net/discord.ts` call `fetch`, and the deploy CSP's `connect-src` allows nothing but the app's own origin and `https://discord.com/api/webhooks/`. Push (#99) needs no CSP change: the browser talks to its own push service, and the page only calls `pushManager` through `src/platform/pushPort.ts`.
- **Push carries nothing** (#99, ADR-0012). Every notification is exactly "Something new in Reconcile" with the tag `reconcile` and no other option (`src/sw/notify.ts`), push request bodies hold only `endpoint` or `not_before`, and registrations and nudges take their mailbox only from `mailboxAt` (`src/store/mailbox.ts`), which follows the group's current key (#98) and the relay's week (#110). A read-only archive (#108) sends no push request at all. Tests use `src/test/fakePush.ts`, never a real push service.
- **Quiet safety:** protective features live in Settings and aren't promoted (ADR-0018).
- **First run gates keys.** Nothing makes keys behind the iOS install gate or before the pilot notice (`src/app/FirstRunGate.tsx`, spec §8.1). A device whose keys are locked with a passkey syncs, sweeps archives and signs nothing until the unlock screen opens them (#95). Every write of key material, the relay backup key (#97), a shared personal Document's seed and keys (#255), a sent application's reply keys (#265) and a recovering device's request seed and X25519 key (#118) and the steward's secret (#488, `src/store/stewardKey.ts`) included, goes through the store's one write path, `keepKeys`, which seals it into the vault when there is one and refuses while it's locked, and anything that hands keys on (Save a backup, Link a new device, #96) calls `Store.requireUnlocked()` first. A record that keeps secrets beside what it says splits through `src/store/sealing.ts`, one mechanism for every such store: its secrets go into the vault by store and id, and the record keeps the rest, so a new kind adds a sealing, not a vault format, as #118's recovery request did. Only `src/platform/webauthn.ts` reaches `navigator.credentials` (ESLint enforces it). The service worker is `src/net/serviceWorker.ts`, built to `/sw.js` by `plugins/serviceWorker.ts`; it never caches `/v1`, and its push and notification-click handlers come from `src/sw/notify.ts` (#99).
- **The landing page and the painting** (ADR-0078, DESIGN.md). A new visitor's plain visit in a browser tab starts on the landing page (`src/screens/Landing.tsx`), before the install gate and the notice. It stores nothing; its words are `messages.landing`, and its classes all start `lp-`. `../painting/paint.py` writes `public/painting/` (the landing page's background, which the service worker never keeps) and `public/edges/` (the few pixels some screens show at their edges, which it does). A screen opts in with `data-scene` on its page shell; `src/styles/scenes.test.ts` lists which screens are painted and which stay plain, and fails until a new screen is on one list.
- **Bedfellows stays on the device** (#473, ADR-0080 §5). `src/bedfellows/` turns the reader's own Documents and public shelf entries into ranked rows in a module worker (`worker.ts`, built by Vite from the app's origin; `client.ts` is the page's side). It imports no React, UI code, `src/net` or `src/store` (dependency-cruiser's `bedfellows-stands-alone`), so the reader's text, vectors and scores live only in that worker's memory for one run. Every threshold is in `thresholds.ts`, set on the corpus's `tune` split with `harness.ts` (#474); `held-out` numbers come only from `heldOutReport`. Models sit behind the `Embedder`, `StanceJudge` and `Splitter` ports, and `standIns.ts` holds the stand-ins each later issue replaces.
- **Bedfellows' model** (#476, ADR-0080 §2). ONNX Runtime Web and tokenizers.js, pinned exactly, are imported only by `src/bedfellows/runtime.ts` (dependency-cruiser's `only-runtime-ts-imports-the-runtime`). The model, tokenizer and runtime wasm are pinned by SHA-256 in `src/net/modelPins.ts` and fetched only through `src/net/modelFiles.ts`, which only `src/bedfellows/embedder.ts` may import; each file's hash is checked before use. `./scripts/models.sh` fetches the model and tokenizer into the gitignored `.models/`, the build checks them and writes `dist/models/`, and a missing model is only a warning unless `RECONCILE_MODELS=required`, which `deploy.sh` sets, so tests and CI run on a tiny in-memory model (`src/test/tinyModel.ts`) with no third party. The deploy CSP's `script-src` adds `'wasm-unsafe-eval'` so the worker can compile the runtime's WebAssembly, and nothing else; the service worker keeps `/models/` on first use, never at install. `./scripts/measure-model.sh` serves a page to measure the model on a phone.
- **A busy control holds presses** (#193). React Aria's usePress starts a press on a disabled control and clicks it itself 80 ms later, which re-sends a submit button's form or flips a checkbox, radio or switch once it's enabled again. So a control disabled while its action runs takes `holdPresses` (`src/app/holdPresses.ts`) as `onPointerDownCapture` on it or its row. ESLint holds every disabled submit `Button` to this; check toggles by hand. A plain `onPress` button needs nothing, since no `onPress` runs for a press that started while disabled.
- **Keep the CSP clean.** The deploy CSP (spec §9) blocks inline `<style>` elements, `style` attributes in markup and `data:` URLs. React's `style` prop is fine: it sets styles through the CSSOM. React Aria's pressable `<style>` is claimed in `index.html`, and `src/styles/pressable.css` ships its rule instead; `src/styles/pressable.test.tsx` fails if React Aria changes it (#150). Its iOS scroll-lock `<style>` has no id, so the CSP allows that one text by its hash in `style-src-elem`; `src/styles/scrollLockStyle.test.tsx` fails if React Aria changes it, and `e2e/ios-scroll-lock.spec.ts` opens a Modal as an iPhone under the CSP (#153). Never add `'unsafe-inline'`.

## Toolchain

- **Stack:** React 19, Vite, TypeScript (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`), and React Aria Components
- **Testing:** Vitest + Testing Library (globals off: import `describe`/`it`/`expect` from `vitest`), and Playwright with `@axe-core/playwright` for the end-to-end loop (`e2e/`, `tsconfig.e2e.json`)
- **Linting:** ESLint 9 flat config with `strictTypeChecked`, jsx-a11y strict, and complexity ≤ 10
  - ESLint stays on 9 until `eslint-plugin-jsx-a11y` supports 10
- **Coverage:** ≥ 90% lines, ≥ 85% branches, enforced in `vite.config.ts`
- **Architecture:** `plans/architecture/.dependency-cruiser.cjs`
  - `src/engine`, `src/crypto`, `src/store`, `src/door` (#121) and `src/recovery` (#118) may not import React or UI code
  - network libraries belong in `src/net/` only
  - only `src/crypto` imports `@noble/*`, and `src/crypto` imports no other third-party package but `shamir-secret-sharing`, which only `src/crypto/shares.ts` imports (#109)
- **Tracked sources:** `scripts/tracked.sh` fails when git ignores anything in `client/` but tool output, because CI's checkout wouldn't have it (the root's Python `build/` rule once hid `client/build/`, #76)
- **Audit:** `scripts/audit.sh`: `npm audit --audit-level=moderate`, production dependencies with no exception. A dev-tooling advisory with no patched release passes only while it's on `.npm-audit-known-vulnerabilities` with an `expires=` date at most 30 days out, which `scripts/auditKnown.mjs` enforces (#495; the cve-remediation skill's last resort)
  - `package.json` `overrides` pin `minimatch` and `qs` to patched releases. Remove an override once its upstream package ships the fix
- **Fonts:** self-hosted through `@fontsource-variable/*`, never fetched from a third party

Detailed generic guidance is in [`.claude/docs/`](.claude/docs/).
